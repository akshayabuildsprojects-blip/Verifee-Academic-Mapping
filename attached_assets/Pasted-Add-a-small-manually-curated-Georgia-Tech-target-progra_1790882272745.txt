### Application behavior

Update Step 3, "Select Target", so the user can select:

1. MS Analytics
2. MS Computer Science
3. MS Industrial Engineering

After a program is selected, show its stored background requirements underneath the dropdown.

The mapping engine must use ONLY these stored requirements as the target criteria.

For each requirement, compare the student's extracted academic record against:
- course titles;
- course descriptions if available;
- course codes;
- credits;
- grades;
- learning outcomes or syllabus information if available.

Return one of:

- Covered
- Partially Covered
- Potential Gap
- Insufficient Evidence

Also return:
- matching student course(s);
- evidence;
- concise rationale;
- confidence: High / Medium / Low.

### Important distinction

Do not describe all stored criteria as mandatory admissions prerequisites.

Respect the `requirementType` and `importance` fields.

For example:

- MS Analytics has specifically published prerequisite/background expectations.
- MS Computer Science describes recommended/expected preparation and uses holistic admissions.
- MS Industrial Engineering describes expected quantitative preparation.

The UI must preserve these distinctions.

### Source transparency

On the mapping results page, show:

"Target criteria sourced from Georgia Tech program materials."

Provide the stored source title and `lastChecked` date in a small expandable "Source details" section.

Do not allow the AI to invent additional Georgia Tech requirements.

### Demo scope

Do not scrape Georgia Tech dynamically.

Do not add more programs yet.

Keep this JSON manually editable so the dataset can be reviewed and corrected before the competition demo.
