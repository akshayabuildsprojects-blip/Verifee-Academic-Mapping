Build a full-stack web MVP called **Verifee**, an AI-powered preliminary academic credential interpretation and course-mapping platform.

### Product purpose

Verifee helps users understand an academic credential from another university or education system and preliminarily compare the student's prior coursework against selected requirements from a target university program.

This MVP is for the ATL Innovation Cup, so prioritize a polished, demonstrable end-to-end workflow over production-scale functionality.

### Core user flow

1. User lands on a clean Verifee homepage.
2. User uploads an academic credential/transcript.
3. User selects a target institution and target program/course from a small predefined dataset.
4. Verifee displays:
   - credential information extracted from the document;
   - verification status;
   - normalized academic information;
   - preliminary course/prerequisite mapping;
   - evidence supporting each mapping;
   - areas where there is insufficient evidence.
5. User sees a clean preliminary report.

### Important product distinction

Keep these concepts separate:

**Credential verification**
Determines whether the document can be independently validated.

Possible statuses:
- Digitally verified
- Verification unavailable
- Verification failed
- External credential evaluation recommended

Do NOT imply that an uploaded PDF is verified simply because AI can read it.

**Credential interpretation**
Extracts and normalizes:
- institution
- country
- qualification
- major/field
- graduation date if present
- courses
- grades
- credits / academic units

**Academic mapping**
Compares prior coursework against target academic requirements.

Possible results:
- Covered
- Partially covered
- Potential gap
- Insufficient evidence

This is preliminary decision support only. Never claim official transfer-credit equivalency, admissions eligibility, or official U.S. degree equivalency.

### MVP credential scope

For this prototype:
- English-language academic credentials only.
- One credential format should eventually support OpenCerts verification.
- One European standardized/digital credential example will also be tested.
- Other PDFs can be interpreted but should show "Verification unavailable" unless a supported verification method succeeds.

For the first build, create the verification layer as a modular service/interface so OpenCerts verification can be connected next.

### Target curriculum

Do NOT ingest an entire university catalog.

Create a small local sample dataset for Georgia Tech with approximately 3–5 target courses/program requirements.

Each requirement should contain:
- target name/course code
- requirement description
- prerequisite concepts or competencies
- optional course description

Store this initial sample dataset locally in JSON so it is easy to edit.

### Preliminary mapping output

For each target requirement, display:

- requirement
- matching student course(s)
- result: Covered / Partially covered / Potential gap / Insufficient evidence
- concise rationale
- evidence used
- confidence: High / Medium / Low

Do not use a meaningless numerical percentage as the primary output.

### Pages

#### 1. Landing / Upload
Minimal professional design.

Headline:

Short explanation:
Verifee interprets academic credentials and creates a preliminary mapping against a target academic program.

Main CTA:
**Analyze a credential**

Upload area should support PDF initially.

Target:
Georgia Institute of Technology

Target program/course:
dropdown using sample data.

#### 2. Analysis state
Show a professional progress workflow:

Reading credential
→ Checking verification options
→ Structuring academic record
→ Comparing coursework
→ Preparing report

#### 3. Results page

Sections:

**Credential**
Institution, degree, major, country, dates.

**Verification**
Clear status card.

**Academic record**
Extracted courses in a readable table.

**Target academic mapping**
Cards/table showing Covered, Partial, Gap or Insufficient Evidence.

**Items requiring review**
Clearly surface uncertain interpretations.

At bottom show:

"Verifee provides preliminary academic interpretation and mapping. It is not an official credential evaluation, admissions decision, or transfer-credit determination."

### Design

The product should feel like a credible education/credential technology product rather than a hackathon template.

Style:
- minimal
- modern
- high-trust
- lots of whitespace
- restrained use of color
- clear typography
- professional enough for a university administrator
- not playful or gamified

Use cards, subtle borders, status badges, and a strong information hierarchy.

Responsive desktop-first design.

### Technical requirements

Use:
- TypeScript
- a modern React/full-stack framework appropriate for Replit
- Tailwind or equivalent utility styling
- modular services for AI extraction, verification, and academic mapping
- Zod or another schema validation library for structured data

Do NOT add:
- authentication
- payments
- user accounts
- complex dashboards
- unnecessary database functionality

unless required later.

Initially use sample/mock credential analysis data so the complete UI flow works before connecting AI.

Structure the code so the mock extraction service can later be replaced by an OpenAI API call.

### First milestone

For this first iteration, build:

- polished landing/upload screen
- target selection
- analysis/loading experience
- complete results/report screen
- editable sample Georgia Tech requirements
- mock transcript data flowing through the complete UI
- modular service structure for extraction, verification and mapping

Do NOT implement OpenCerts or the OpenAI API yet.

Run the app, test the complete user journey, and fix UI/runtime errors before finishing.
